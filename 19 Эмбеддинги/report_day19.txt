0. ОСОБЕННОСТЬ СРЕДЫ
На учебном ПК не установлена библиотека sentence-transformers
(и torch), поэтому по разделу 11 методички используется резервный
вариант — учебный эмбеддер на хешах слов и символьных n-грамм.
Он даёт разреженный вектор из 2048 чисел, косинусное сходство считается
той же формулой. Это не нейросетевая модель: близость получается
лексической, а не глубоко семантической. Весь алгоритм Дня 19 при этом
отработан полностью: encode → similarity → лучший чанк → метаданные.

В embeddings.py оставлен и основной путь:
from sentence_transformers import SentenceTransformer
model = SentenceTransformer("sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")

Функция load_embedder() сначала пытается загрузить эту модель, а при
ImportError или ошибке загрузки автоматически переходит на HashEmbedder.
Если установить sentence-transformers и скачать модель, все скрипты
начнут использовать её без изменения кода.

8. ИТОГОВАЯ ПРОГРАММА final_day19.py
Что делает:
1) загружает 13 чанков из chunks/ вместе с source и chunk_id;
2) загружает один эмбеддер (SentenceTransformer или резервный);
3) один раз считает embeddings всех чанков;
4) получает вопросы через input(); если терминала нет — берёт готовые;
5) считает similarity вопроса со всеми чанками;
6) находит max(score) и его индекс;
7) выводит source, chunk_id, score и полный текст лучшего чанка;
8) повторяет поиск для пяти вопросов.

Полный код:

import os
from pathlib import Path

from embeddings import ask_questions, load_chunks, load_embedder, search

os.chdir(os.path.dirname(os.path.abspath(__file__)))

DEFAULT_QUESTIONS = [
    "Почему возникает NameError?",
    "Как объявить функцию через def?",
    "Как открыть файл с помощью open()?",
    "Что делает list.append()?",
    "Как создать список в Python?",
]


def main() -> None:
    embedder = load_embedder()
    chunks = load_chunks()

    documents = {chunk["source"] for chunk in chunks}
    print("Документов:", len(documents))
    print("Чанков:", len(chunks))
    if len(chunks) < 10:
        print("Внимание: по методичке нужно минимум 10 чанков.")

    print("Модель:", embedder.name)
    print("Размерность embedding:", embedder.dimension)
    if embedder.is_fallback:
        print("Примечание: Sentence Transformers не установлена,")
        print("поэтому используется резервный учебный эмбеддер.")

    texts = []
    for chunk in chunks:
        texts.append(chunk["text"])

    chunk_embeddings = embedder.encode(texts)
    print("Форма матрицы embeddings:", chunk_embeddings.shape)

    questions = ask_questions(DEFAULT_QUESTIONS)
    for question in questions:
        best = search(embedder, chunks, chunk_embeddings, question)[0]

        print("\n" + "=" * 60)
        print("Вопрос:", question)
        print("source:", best["source"])
        print("chunk_id:", best["chunk_id"])
        print("score:", round(best["score"], 4))
        print("text:")
        print(best["text"])


if __name__ == "__main__":
    main()

13. ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ
1. Embedding — числовое представление текста в виде вектора.
2. Вектор — список чисел; сегодня это обычный список или массив.
3. Тексты превращают в числа, чтобы их можно было сравнивать и искать
   программно, а не только читать глазами.
4. В RAG эмбеддинги нужны, чтобы закодировать чанки и вопрос, сравнить
   их и выбрать фрагменты, которые потом передаются модели.
5. Similarity — числовая оценка похожести двух векторов.
6. Cosine similarity — косинус угла между векторами; чем ближе векторы
   по направлению, тем выше значение.
7. Похожие по смыслу тексты модель располагает рядом в векторном
   пространстве, поэтому косинус между ними больше.
8. model.encode() преобразует текст или список текстов в вектор/матрицу.
9. Размерность — количество чисел в одном embedding.
10. Одна модель использует одно векторное пространство и одну
    размерность, поэтому все её векторы можно сравнивать.
11. Передать список текстов: model.encode(texts); получится матрица,
    где строка — вектор одного текста.
12. model.similarity() считает матрицу косинусных сходств между двумя
    наборами векторов.
13. Вектор совпадает сам с собой по направлению, косинус равен 1.
14. Получить embedding вопроса и вызвать similarity(query_embedding,
    chunk_embeddings) — получится score для каждого чанка.
15. max() находит наибольшее значение score.
16. scores.index(max_score) или numpy.argmax(scores).
17. source нужен, чтобы указать документ, из которого взят фрагмент,
    и проверить ответ по первоисточнику.
18. chunk_id нужен, чтобы отличить фрагменты одного документа и найти
    нужный файл чанка.
19. Векторы чанков считаются один раз, потому что это дорого, а корпус
    между вопросами не меняется; готовые embeddings можно сохранить.
20. Разные модели дают разные размерности и разные пространства,
    поэтому их векторы несопоставимы.
21. Semantic search — поиск по смысловой близости, а не по точному
    совпадению слов.
22. Embedding-поиск возвращает самый близкий из имеющихся чанков, но
    если нужной информации в корпусе нет, лучший score может быть
    нерелевантным.
23. Top-k — несколько лучших результатов, которые передаются дальше.
24. Следующий этап — векторное хранилище (FAISS, Chroma) и построение
    полной RAG-цепочки с передачей найденных чанков в LLM.
