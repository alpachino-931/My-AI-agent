ЗАДАНИЕ 2. Исходная программа
Запрос: 
Язык: Python
Код:
a = 10
b = 0
print(a / b)
Ошибка: ZeroDivisionError: division by zero
Ответ: Причина: во второй строке происходит деление на ноль. 
Объяснение: операция a / b требует, чтобы b было не равно нулю. 
Исправленный код: if b != 0: print(a / b). Совет: перед делением проверяйте делитель.

ЗАДАНИЕ 3. План из 6-8 шагов
1. Импортировать нужные библиотеки и ChatModelOptions.
2. Считать настройки (ключ, сертификат) из .env.
3. Запросить у пользователя код/ошибку (обязательное поле), ограничения и желаемый результат с помощью input().strip().
4. Спросить формат ответа (1 или 2). Проверить на пустоту и правильность ввода, если ошибка — sys.exit().
5. Сформировать user_prompt через f-строку, подставив все переменные.
6. Создать список messages, где system — это SYSTEM_PROMPT, а user — это user_prompt.
7. Создать ChatCompletionRequest с добавлением ChatModelOptions (temperature=0.2, max_tokens=400).
8. Отправить запрос, извлечь ответ. Записать user_prompt в last_prompt.txt, а answer в last_answer.txt.

ЗАДАНИЕ 4. Анализ инструкции (SYSTEM_PROMPT)
1. Роль: "Ты — помощник-программист по поиску и исправлению ошибок в коде."
2. Задача: "определить наиболее вероятную причину ошибки; объяснить... показать исправление..."
3. Контекст: "Пользователь присылает фрагмент кода и сообщение об ошибке."
4. Ограничения: "Не придумывай несуществующие функции... соблюдай ограничения пользователя."
5. Формат ответа: "Причина / Исправленный код / Совет."

ЗАДАНИЕ 5. Общие правила и данные
В SYSTEM_PROMPT только общие правила: роль, задача, запреты, формат ответа. Случайных данных одного примера (язык, код, ограничение) там нет.
Конкретные данные передаются в user: язык, код/ошибка, ограничение, желаемый результат, выбранный формат.
Проверено по main.py: messages[0] — system с SYSTEM_PROMPT, messages[1] — user с актуальным user_prompt.

ПРОВЕРЬТЕ ПОНИМАНИЕ
Вопрос: Почему название SYSTEM_PROMPT само по себе не делает текст системным сообщением? 
Ответ: Потому что для модели важен не текст названия переменной, а атрибут role="system" в объекте ChatMessage. Именно эта запись указывает API, что это инструкция.

ЗАДАНИЕ 10-11. Обязательные разделы и выбор формата
В SYSTEM_PROMPT заданы разделы: 1. Причина, 2. Объяснение, 3. Исправленный код, 4. Совет. Три обязательных: Причина, Исправленный код, Совет («Объяснение» — дополнительный раздел).
Проверка обычного запроса (print("Hello) . Syntax error): в ответе появились все четыре раздела с полезным содержанием — причина (незакрытая кавычка), объяснение, исправленный код print("Hello"), совет.
В коде добавлен input() для выбора 1 (краткий) или 2 (пошаговый). При неверном вводе (например, 3) выдается ошибка. В режиме 1 агент пишет коротко (только суть). В режиме 2 — подробно расписывает шаги.

Классификация: "Классифицируй ошибку как SyntaxError, RuntimeError или LogicalError.

Запрос: "Извлеки поля из фразы: 'Код на Python, ошибка IndexError'. Поля: Язык, Ошибка, Ограничение. Если чего-то нет, пиши 'не указано'."
Ответ: Язык: Python. Ошибка: IndexError. Ограничение: не указано.

(С SYSTEM_PROMPT тот же запрос ушёл бы по правилу «сначала запроси код», поэтому эксперимент запускался с user-сообщением без system.)

ВОПРОС ДЛЯ ОБЪЯСНЕНИЯ (К формату)
Ограничение "ответ из 3 разделов" — это структурное требование (смысл). 
Ограничение длины (max_tokens) — это физическое ограничение токенов. 
Ответ может иметь правильные заголовки, но не решать задачу, если модель просто напишет "Причина: не знаю. Код: нет. Совет: нет".

ЗАДАНИЕ 13. Подключение настроек
Настройки находятся в запросе, потому что они относятся к конкретному вызову ChatCompletionRequest, а не к глобальной настройке клиента.

ЗАДАНИЯ 14-15. Температура (temperature)
Запрос: "Придумай 3 названия для функции проверки пароль".
При 0.2 (3 запуска): check_password, verify_pass, pass_check (однотипно, повторяются).
При 1.0 (3 запуска): password_ninja, secret_guardian, access_shield (разнообразно).
Вывод: Высокая temperature дает больше разнообразия идей, но может нарушить формат. Низкая — стабильнее.

ЗАДАНИЕ 16. Ограничение длины (max_tokens)
Запрос: "Подробно объясни, почему возникает IndexError".
При 80: ответ обрывается на полуслове ("...для этого нужно проверить длину...").
При 400: ответ полный, есть причина и пример кода.
Вывод: 80 токенов не хватило для развернутого ответа.

ЗАДАНИЕ 17. Повторения (repetition_penalty)
При 1.0: модель повторяет фразу "деление на ноль невозможно" 3 раза в одном абзаце.
При 1.05: фраза повторяется 1 раз, текст более связный.
Вывод: 1.05 работает лучше, оставляю это значение.
